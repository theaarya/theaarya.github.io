The test

Is there anything actually left to decide?

Ask it before you build. If the input is already structured, you have done the work the model would have done. Putting an LLM after that point adds cost and variance to something you could have written down.

The talk30 min

Right now the default answer to most automation problems is: make it an agent. We nearly did that with churn, and I am glad we stopped.

Churn at Tutero is mission critical. It touches revenue directly. The original plan was an agent that would handle the whole thing end to end. Then we looked at what that agent would actually be deciding. We already ask the customer a long form, so every detail we need is there, structured, before anything runs. There was nothing left to interpret. The rule was writable as a set of conditions. So we built it as a deterministic workflow instead. No model in the path.

Support and recruitment are different. Judgement is real there, so those are agents. The second half of the talk is about containing them: least-privilege tool access across nine internal systems, and a deny-by-default rule for what agents are allowed to hand to each other.

You leave with the test I use to make the call, and the patterns I use to stop an agent reaching further than I meant it to.

  4. 04The tool-access and delegation patterns I use so an agent cannot reach further than intended.
